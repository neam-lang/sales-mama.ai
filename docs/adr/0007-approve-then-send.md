# ADR-0007: Approve-then-send for email and WhatsApp

- **Status:** accepted (2026-11-02). Supersedes ADR-0001. Sending stays off until the manager sets `enabled: true` in `knowledge/sending.yaml` after the DPO confirms each live market's guardrails.
- **Context:** Drafts-only (ADR-0001) kept a human on every message, but reps asked for outreach to go out from one place, on more than one channel. The claude.ai Gmail connector can create drafts but has no send tool, and WhatsApp business messaging is only allowed through the WhatsApp Business Cloud API (opted-in contacts, approved templates for first contact). Inbound WhatsApp arrives only by webhook, which would need a server (against ADR-0002 and ADR-0004).
- **Decision:**
  - Agents prepare; **the owner rep approves each batch**; only then does it send. Sending goes through one script, `scripts/send.py`, in two steps: `--preview` (read-only: live Gmail draft, every check re-run, a hash per message) and `--send <preview> --items …`, which is on Claude Code's `permissions.ask` list so the rep clicks to approve the exact command. Any message that changed after the preview is refused.
  - `send.py` refuses, whatever the agent says: sending off; the nightly runner (`MAMA_RUNNER`, and `--disallowedTools` in `runner/`); not the owner; suppressed email or domain; outside the market's send window or on a holiday (hard, not advisory); over the daily quota or `max_per_run`; a recipient that differs from the contact page, or added Cc/Bcc; a mailbox that isn't the rep's; WhatsApp without +E.164, recorded consent (`whatsapp_opt_in`, date, `raw/` source) or, outside 24 h after the contact's last WhatsApp reply, an approved template.
  - Email goes out through the Gmail API (`users.drafts.send`) with the rep's own OAuth token (Workspace Internal client; scopes `gmail.compose` + `gmail.readonly`), so what is sent is the draft the rep can see. A `List-Unsubscribe` header is added; the visible unsubscribe line stays.
  - WhatsApp goes out through the Cloud API with the company number. Replies stay manual: the rep pastes them into `/mama-replies`, and STOP or unsubscribe goes to `wiki/suppression.csv`.
  - Secrets live outside the repo in `~/.config/sales-mama/` (mode 600). `connect.py` sets them up; the WhatsApp token is typed by the person, never passed through the model. `guard.py` and `lint.py` block token files and token strings in the repo.
  - The runner, VAMs and the console never send. MCP send, reply and forward tools stay denied. SMS, calls and personal WhatsApp are never automated.
- **Consequences:** every send leaves a row in `log/approvals.csv`, a preview file in `log/outbox/` and a `sent` touch whose `ref` is `gmail:<id>` or `wa:<wamid>`; `eval.py` counts sends without a matching approval, outside the window, to suppressed contacts and WhatsApp without consent (target 0 each). Codex has no ask rules, so in Codex `mama-send` stops after the preview and the rep runs `--send` themselves.
